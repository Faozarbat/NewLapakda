1. Info Proyek & Visi

LapakDA adalah platform "Web Mall" UMKM berbasis mobile-first. UMKM (Resto & Toko) bisa mendaftar gratis, mendapatkan halaman katalog online sendiri, dan membagikan link-nya via WhatsApp. Buyer bisa langsung memesan dan checkout diarahkan ke WA pemilik.

AspekDetail

FrontendBlade + Tailwind CSS (Vite) + Alpine.js
Map & GeolocationLeaflet + OpenStreetMap (Gratis)
Image ProcessingIntervention Image (Auto WebP)
Target Pengguna90% Mobile (PWA First)
EnvironmentLokal: lapakda.test | Prod: lapakda.com

2. Role & Akses

Konsep Akun (Satu Pintu) Tidak ada tabel/role terpisah untuk "Owner" dan "Buyer". Semua masuk ke tabel users. Seseorang otomatis menjadi Owner jika ia memiliki minimal 1 baris data di tabel stores.

UserDashboardLogin via Nomor HP. Bisa bertindak sebagai pembeli, atau mendaftarkan tokonya sendiri.
OwnerKelola TokoBisa CRUD Produk, melihat Order, edit profil toko.

4. Aturan Wajib (Strict)

Aturan UI/UX (Dilarang Keras Melanggar)
  1. NO EMOJI: Wajib gunakan SVG (Heroicons/Lucide). Dilarang pakai emoji di UI.
  2. NO NATIVE ALERT: Dilarang pakai alert(), confirm(), prompt(). Wajib gunakan Modal Alpine.js / Toast.
  3. Mobile-First: Desain dimulai dari layar 375px. Tombol minimal 44px (min-h-[44px]).
  4. Tailwind CSS: Semua styling pakai kelas Tailwind. Dilarang tag <style> manual (kecuali font/animasi).
  5. Panggil Vite: Setiap halaman yang butuh JS wajib ada @vite(['resources/js/app.js']).
Aturan Backend & Keamanan
  1. Harga Snapshot: Saat checkout, harga disalin ke order_items.price. Jangan referensi live ke products.
  2. Authorization Server-Side: Cek kepemilikan (Policy/If-else) sebelum update/delete.
  3. Private Storage: Foto bukti transfer disimpan di storage/app/private/.
  4. Image Processing: Wajib Resize & Convert WebP menggunakan Intervention Image.
  5. HTTPS: Wajib HTTPS untuk production (prasyarat Geolocation API).

5. Struktur URL

Format URL Katalog Toko adalah:

lapakda.com/{kecamatan}/{nama-toko}
  • Contoh: lapakda.com/nongsa/warung-bahagia
  • Slug toko unik per kecamatan, bukan unik global. (Toko A di Nongsa boleh punya nama sama dengan Toko B di Batam Kota).
  • Database constraint: unique(['kecamatan_id', 'slug']).

6. Autentikasi (Nomor HP)

Sesuai keputusan produk, identitas utama login adalah Nomor HP (WhatsApp).

  • Kolom email bersifat opsional (boleh kosong).
  • Nomor HP dinormalisasi ke format 62xxx (misal: 08xx jadi 628xx).
  • Gunakan helper App\Support\PhoneNumber::normalize().
  • Proses verifikasi OTP WA ditunda ke fase selanjutnya.

7. Sistem Cart & Checkout (Paling Kompleks)

7.1 Sistem Cart

  • Disimpan di Session Laravel (bukan database).
  • Setiap toko punya keranjang terpisah (tidak bercampur).
  • Wajib menyertakan ID Produk di array session: "id" => $product->id.

7.2 Opsi Fulfillment

Saat checkout, buyer memilih salah satu:

Self Pickup (Ambil Sendiri)

Ada dua opsi konsumsi per item:

  • Dine-in (Makan di Tempat): Muncul input Nomor Meja jika toko mengaktifkannya.
  • Takeaway (Bungkus).

Catatan: Satu baris produk bisa di-split qty-nya (misal 2 porsi, 1 dine-in, 1 bungkus).

Delivery (Di Antar)

Resto mengantar sendiri via ojek (diatur di WA).

  • Semua item otomatis dianggap takeaway.
  • Buyer wajib mengisi titik lokasi (Latitude/Longitude) via Geolocation API atau Pin Map (Leaflet).

7.3 Nomor Meja

Hanya muncul jika store.has_table_number = true DAN buyer memilih Dine-in. Disimpan sebagai teks bebas (contoh: "A1", "VIP-2").

7.4 Redirect ke WhatsApp

Sistem menyimpan Order ke DB, lalu membuat pesan terformat menggunakan urlencode() dan mengarahkan (redirect) ke wa.me/{nomor_resto}.

8. Pendaftaran Toko

Form wajib saat mendaftar Resto:

  • Nama Toko, Kategori (Resto), Kecamatan.
  • Nomor WhatsApp (Dinormalisasi).
  • Alamat Lengkap.
  • Titik Lokasi (Lat/Long): Wajib drop pin di peta (Leaflet).
  • Jam Operasional: Format JSON (Hari, Jam Buka, Jam Tutup, Status Libur).
  • Setting Nomor Meja: Ya / Tidak (has_table_number).

10. Rencana Monetisasi & Payment

  • Saat ini: Gratis total. Belum ada fee.
  • Rencana ke depan: Fee Rp500 per checkout.
  • Kendala: Pembayaran masih manual (tunai di WA), jadi fee belum bisa ditarik.
  • Solusi (Fase Lanjut): Menggunakan Midtrans untuk pembayaran online. Fee Rp500 dipotong otomatis via fitur split settlement (Iris API).
  • Persiapan DB: Kolom payment_status, payment_method, dan platform_fee di tabel orders sudah disiapkan.

11. Checklist Keamanan

11.1 Upload Gambar (Wajib)

  • Batasi ukuran (max 2MB).
  • Resize otomatis & Convert ke WebP (Intervention Image).
  • Validasi MIME Type (jangan percaya ekstensi).
  • Rename file ke UUID (jangan pakai nama asli user).
  • Hapus file lama saat ganti/hapus produk.

11.2 Aplikasi & Data

  • Authorization Per-Tenant: Toko A dilarang edit produk Toko B (Gunakan Laravel Policy).
  • Validasi Harga: Hitung ulang harga di backend saat checkout (jangan percaya frontend).
  • .env: Jangan commit ke Git.
  • APP_DEBUG: Wajib false di production.
  • HTTPS: Wajib di production (Geolocation API butuh ini).
  • Rate Limiting: Wajib pasang di endpoint checkout & registrasi.
  • Idempotency: Cegah double-submit checkout (token unik).

11.3 Logika Bisnis

  • Cek jam operasional & status toko saat checkout.
  • Cek status ketersediaan produk ulang (saat checkout, bukan hanya saat masuk cart).
  • Toko nonaktif harus tampil halaman "Toko Tutup", bukan 404 polos.
  • Order pakai SoftDeletes (jangan dihapus permanen).

11.4 Privasi Data (UU PDP)

  • Wajib punya halaman Kebijakan Privasi.
  • Jangan simpan histori lokasi user lebih lama dari yang diperlukan.
  • Sediakan opsi input lokasi manual (drop pin) jika user menolak izin GPS.

12. PWA (Progressive Web App)

  • Wajib bisa di-install ke homescreen HP.
  • Gunakan manifest.json dan service worker.
  • Strategi Cache: Halaman = Network-first (jangan sampai data basi). Asset statis = Cache-first.

13. Lessons Learned (Kesalahan Fatal)

Bacaan Wajib untuk Programmer / AI Baru Jangan pernah mengulangi kesalahan ini:
  1. Lupa Fitur Spec: Membangun aplikasi tanpa membaca PRODUCT_SPEC lengkap (misal lupa buat fitur Geolocation).
  2. Pakai Alert Browser: Menggunakan confirm() atau alert() bawaan browser.
  3. Lupa @vite: Memakai Alpine.js tapi lupa memanggil @vite di <head>.
  4. Sembunyikan Elemen Mobile: Menghilangkan panel branding di mobile tanpa alternatif desain.
  5. Relasi Model Hilang: Memanggil hasMany di Controller tanpa mendefinisikannya di Model.
  6. Asal Bikin File: Menyuruh copy-paste kode Controller padahal file-nya belum di-generate via artisan.

  3. Edit migration lama (Wajib buat migration baru).
